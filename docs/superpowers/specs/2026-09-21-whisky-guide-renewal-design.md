# Japanese Whisky Guide リニューアル（Phase 1＋2）設計ドキュメント

**作成日:** 2026-09-21
**対象:** OtaSanpot/whisky-site（公開中: https://ota-sanpot.github.io/whisky-site/）
**もとになったもの:** CEO提供の「サイトリニューアル設計書」。このドキュメントは、その設計書を現在のサイトの決まりごと（事実は公式で裏取り・出典必須、見立ては明示、価格は載せない）に合わせて具体化したもの。

---

## 1. 目的

「自分に合うジャパニーズウイスキーを見つける」ところまで、サイトの中で完結させる。

```
知る → 探す → 比較する → 自分に合う1本を見つける → 次の1本を見つける
```

目指すのは「ジャパニーズウイスキーを探すための検索・診断・図鑑サイト」。読み物サイトでもニュースサイトでもない。

## 2. 今回の決定事項（CEO確認済み）

|------|------|
| 価格 | **載せない**。設計書の「価格から探す」「予算の質問」「価格帯表示」は作らない。代わりにタイプ・シーンの検索を強くする |

## 4. データ設計

### 4.1 いまあるもの（変えない）

`id` / `name` / `nameEn` / `short` / `kana` / `aliases` / `maker` / `type` / `standard` / `standardNote` / `limited` / `components` / `originNote` / `componentsNote` / `casks` / `taste{line,x,y}` / `serve{straight,rock,highball,mizuwari}` / `makerServe` / `next` / `official` / `story` / `specs` / `sources` / `look`

蒸溜所は `id` / `name` / `nameEn` / `kana` / `maker` / `pref` / `address` / `founded` / `lead` / `features` / `sources`。

### 4.2 足すもの（96銘柄すべて）

| 項目 | 内容 | 決め方 |
|------|------|--------|
| `profile.sweetness` | 甘さ 1〜5 | 下の規則で自動算出し、必要なら手で調整 |
| `profile.fruitiness` | フルーティ 1〜5 | 同上 |
| `profile.smokiness` | スモーキー 1〜5 | 同上 |
| `profile.richness` | 濃厚 1〜5 | 同上 |
| `profile.drinkability` | 飲みやすさ 1〜5 | 同上 |
| `finish` | 余韻の長さ（短め／中くらい／長い） | 公式の「余韻」の記述から。なければ濃厚さで決める |
| `scenes` | シーンのタグ（下の6種） | 下の規則で自動付与 |
| `addedAt` | 掲載日（新着の並び替え用） | 既存96銘柄は追加した日付 |

**5段階の決め方（サイト独自の目安）**

味の地図の位置（x: 華やか−1 ↔ スモーキー+1、y: やわらか−1 ↔ 濃厚+1）と、公式の説明・味の一言に出てくる言葉から決める。

- スモーキー = `3 + x*2` を四捨五入して1〜5に収める
- 濃厚 = `3 + y*2` を四捨五入して1〜5に収める
- フルーティ = `3 - x*1.5` を四捨五入し、「フルーティ／果実／りんご／洋梨／バナナ／柑橘／プラム／ベリー／桃／メロン」があれば+1
- 甘さ = 3 を起点に、「甘」で+1、「蜂蜜／バニラ／キャラメル／黒糖／チョコ／はちみつ」で+1、「ドライ／キレ／すっきり」があって「甘」がなければ−1
- 飲みやすさ = 3 を起点に、度数45%未満で+1、「軽やか／やわらか／なめらか／すっきり／飲みやすい」で+1、スモーキーが4以上で−1、度数50%以上で−1

**シーンのタグ（サイト独自の目安）**

| タグ | 付ける条件 |
|------|-----------|
| 初めての1本 | 飲みやすさ4以上、スモーキー3以下、限定品でない |
| 普段飲み | 限定品でなく、ブレンデッド系かグレーン系で、飲みやすさ3以上 |
| プレゼント | 年数表記がある、または大手3社（サントリー・ニッカ・キリン）のシングルモルト |
| 特別な日 | 年数表記が12年以上、または限定品 |
| 食事と一緒に | ハイボールか水割りが◎ |
| バーで飲みたい | シングルモルト・ピュアモルト・ブレンデッドモルトで、限定品でない |
| （受け皿） | どれにも当てはまらなかった銘柄は「バーで飲みたい」にする。度数が高く飲み慣れた人向けの銘柄が残るため |

### 4.3 地方の区分

都道府県を地方にまとめる（蒸溜所検索と一覧の絞り込みで使う）。北海道／東北／関東／甲信越／東海／北陸／近畿／中国／四国／九州・沖縄。

## 5. 画面

### 5.1 トップ（`#/`）

「読むページ」ではなく「探すページ」にする。上から順に。

1. **ファーストビュー**: 「あなたに合うジャパニーズウイスキーを見つける。」／サブコピー「味わい・タイプ・飲み方・シーンから、あなたにぴったりの1本を探せます。」／ボタン2つ（**ウイスキーを探す**＝一覧へ、**3問で診断する**＝診断へ）／銘柄名の検索窓
2. **何から探しますか？**: 6枚のカード（味わい・タイプ・飲み方・シーン・蒸溜所・診断）
3. **まずはここから**: 編集部が選ぶ定番8本（響 JAPANESE HARMONY／山崎／白州／知多／シングルモルト余市／シングルモルト宮城峡／富士 シングルブレンデッド／角瓶）。「編集部が選ぶ定番」と明記する（人気順ではない）
4. **診断への導線**: 「あなたに合う1本を探してみませんか？」＋3問で診断
5. **味わいMAP（簡易）**: 全銘柄の点を出し、「もっと見る」で味わいMAPページへ
6. **蒸溜所**: 地方別のカード（件数つき）
7. **今日の1本**: その日の1本を出し、ページへ
8. **新しく載せた銘柄**: 掲載日の新しい順に6本

### 5.2 銘柄一覧（`#/list`）

- 検索窓（読み・英字対応。いまの検索の仕組みをそのまま使う）
- 絞り込み：タイプ／地方／蒸溜所／味わい／飲み方（◎のもの）／シーン／表示基準の区分
- 味わいの絞り込みの意味：甘い＝甘さ4以上、フルーティ＝フルーティ4以上、濃厚＝濃厚4以上、スモーキー＝スモーキー4以上、爽やか＝飲みやすさ4以上かつ濃厚2以下
- 並び替え：おすすめ（編集部が選ぶ定番8本を先頭に、次に飲みやすさの高い順、同点は名前順）／名前／新着（掲載日の新しい順）／度数が高い／度数が低い
- 条件と並び順はURLに残す（例 `#/list?type=single-malt&taste=smoky&sort=name`）
- 件数を出し、0件のときは条件をゆるめる案内を出す
- 旧URL（`#/?q=` や `#/?taste=`）は一覧へ引き継ぐ

### 5.3 銘柄詳細（`#/whisky/<id>`）

設計書の順に組み替える。

1. 銘柄名／英字／メーカー・タイプ／表示基準のバッジ／限定の表示／ボトル図
2. 特徴（味の一言）
3. **味わい（5段階）** を棒で表示＋「サイト独自の目安」の表示（詳細ページでは小さな味の地図をやめ、5段階に置き換える。地図は味わいMAPページで見る）
4. 香り・味・余韻（公式の説明の要約。余韻の長さも表示）
5. おすすめの飲み方（◎○△＋メーカー推奨があれば別枠）
6. **こんな人におすすめ**（シーンのタグと5段階から作る文。見立てと明記）
7. 産地・中身の原酒（蒸溜所へのリンク）
8. **次の1本**（3本。「味わいが近い」「タイプが違う」「同じ蒸溜所」のように理由を明示）
9. **関連する比較**（この銘柄が入っている比較ページへのリンク）
10. 原酒と樽／造り手と歴史／スペック／出典

### 5.4 診断（`#/find`）

3問。1画面に並べ、選ぶたびに結果が入れ替わる（送信ボタンなし）。条件はURLに残す。

- Q1「普段どんなお酒を飲みますか？」ビール／ワイン／日本酒／焼酎／ハイボール／あまり飲まない
- Q2「どんな味が好きですか？」甘め／爽やか／濃厚／スモーキー／フルーティ／よくわからない
- Q3「どんなときに飲みますか？」初めての1本／普段飲み／プレゼント／特別な日／食事と一緒に／バーで飲みたい

**点の付け方**（すべて見立て。サイト独自の目安と明記）

| 答え | 加点 |
|------|------|
| ビール | 飲みやすさ＋ハイボールが◎なら加点 |
| ワイン | フルーティ・甘さに加点 |
| 日本酒 | 飲みやすさ・やわらかさ（濃厚の低さ）に加点 |
| 焼酎 | 濃厚・樽の個性に加点 |
| ハイボール | ハイボールが◎の銘柄に加点 |
| あまり飲まない | 飲みやすさに強く加点、スモーキーに減点 |
| Q2の味 | 対応する5段階の値に応じて加点 |
| Q3の場面 | そのシーンのタグを持つ銘柄に加点 |

結果は**上位3本**（理由の1行つき）と、**あなたのタイプ**（華やか・フルーティ系／やさしい軽快系／スモーキー系／濃厚・熟成系）。そのあとの導線は「この3本を比較する」「別の条件で探す」「味わいMAPを見る」「今日の1本を見る」。

### 5.5 比較（`#/compare?a=<id>&b=<id>`）

- 2本を並べて比較。銘柄は画面上で選び替えられる
- 比較する項目：タイプ／度数／容量／産地・蒸溜所／表示基準の区分／味わい5段階／向いている飲み方／余韻／限定
- 最後に「こんな違いがあります」として、差が大きい項目を2つ取り上げた文を出す（順位付けはしない。見立てと明記）
- トップと詳細ページから、定番6組へ1タップで行けるようにする：山崎 vs 白州／余市 vs 宮城峡／山崎 vs 響／白州 vs 知多／竹鶴 vs 宮城峡／富士 vs 知多

### 5.6 味わいMAP（`#/map`）

- 軸は設計書どおり。**横＝軽やか↔濃厚、縦＝フルーティ↔スモーキー**（いまの地図とは縦横が入れ替わる）
- データの `taste.x`（華やか↔スモーキー）と `taste.y`（やわらか↔濃厚）はそのまま使い、描くときだけ入れ替える（横に `y`、縦に `x` を使う）。データを書き換えないので、既存の出典や見立てはそのまま
- 全銘柄を点で置き、点をタップすると名前と一言が出て、銘柄ページへ行ける
- 絞り込み：すべて／フルーティ系／スモーキー系／甘い系／軽やか系

### 5.7 今日の1本（`#/today`）

- その日の日付から決まる1本（同じ日なら何度開いても同じ）
- 銘柄名・ボトル図・一言・こんな味・おすすめの飲み方・「この銘柄を見る」
- 「もう一度選ぶ」で別の1本（URLにその番号が残る）

### 5.8 蒸溜所（`#/distilleries`、`#/distillery/<id>`）

- 一覧は地方別。カードに蒸溜所名・都道府県・運営会社・代表銘柄を出す
- 詳細はいまの内容（所在地・創業・特徴・この蒸溜所の銘柄・原酒が使われている銘柄・出典）を引き継ぐ
- 全国MAPと見学情報はPhase 3なので今回は作らない

### 5.9 表示基準（`#/standard`）

いまのページを引き継ぐ。設計書17章（ジャパニーズウイスキーと日本のウイスキーの整理）は、この5区分の説明で満たす。

## 7. 事実と見立ての線引き（変えない）

- **事実**：産地・蒸溜所・原酒の構成・度数・容量・表示基準の区分・歴史。公式ページで裏取りし、各ページに出典と確認日を出す
- **見立て**：味の一言・味わい5段階・余韻の長さ・シーンのタグ・こんな人におすすめ・診断・次の1本・比較の説明文。画面に「サイト独自の目安」「編集部の見立て」と明記する
- 公式の説明を載せるときは要約し、「メーカー公式の説明を要約」と書く

## 8. モバイルの決まり

- 基準幅375px、左右の余白16px、文字は本文15px（768px以上で16px）
- カード型のUI、ボタンは高さ44px以上
- 横スクロールは「次の1本」など意図した場所だけ
- 銘柄詳細は「名前→ボトル→特徴→味わい→おすすめ→次の1本」の順を守る
- 絞り込みは折りたたみ（開くと選べる）にして、初めから縦に長くしない

## 9. テスト

- 既存52件を新しい構成に合わせて書き換え、画面ごとにテストを足す（目安70件以上）
- 追加する主なもの：一覧の絞り込みと並び替え、旧URLの引き継ぎ、5段階の算出規則、シーンのタグ、診断の点の付け方、比較の差分の文、味わいMAPの軸、今日の1本が同じ日なら変わらないこと
- データのテスト：全銘柄に5段階・余韻・シーン・掲載日があること、5段階が1〜5であること、価格の表記がないこと
- 実機幅の確認：主要画面（トップ・一覧・詳細・診断・比較・MAP・今日の1本）をスマホ幅で見て、崩れと横スクロールがないこと

## 10. 今回やらないこと

価格に関するすべて（価格検索・予算・価格帯表示）／ボトル写真／全国の蒸溜所MAP／見学情報／基礎知識のページ／ウイスキー旅行／バー情報／イベント／購入導線・アフィリエイト／人気ランキング（根拠が取れないため「編集部が選ぶ定番」に置き換え）。

## 11. 進め方

1. ファイルを分ける（index.html / styles.css / data.js / app.js）。ここでは見た目と機能を変えない
2. データに5段階・余韻・シーン・掲載日を足す
3. 一覧・トップを作る
4. 銘柄詳細を組み替える
5. 診断を3問の新方式にする
6. 比較・味わいMAP・今日の1本を作る
7. 蒸溜所一覧（地方別）を作る
8. 通しで確認して公開

各段階でテストを通し、コミットする。公開は最後にまとめて行う。
